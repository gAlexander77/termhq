# Application recording handoff

The homepage pairs real application screenshots with three workflows. Keep the existing abstract glass artwork decorative; do not replace it with an inaccurate application mockup.

## Current screenshots

`AppScreenshots.astro` presents three user-supplied Windows captures from September 7, 2026: Default (`150110`), Dracula (`150147`), and Monokai (`150224`), in that order. Originals are preserved in `site/src/assets/screenshots/`; Astro generates responsive WebP previews, and the full-size links open the original PNGs.

The repository README reuses these same PNGs: Default is the main product screenshot, with Dracula and Monokai in an expandable marketplace-theme section. Keep these paths stable when replacing captures so both surfaces stay in sync.

The gallery sits immediately after the hero: this is the visitor's first view of the actual product, so lead with the workspace and its capabilities, not theming. The secondary theme selector uses a native radio group, with no autoplay or JavaScript dependency. Default is TermHQ's own theme; Dracula and Monokai are VS Code themes installed through its integrated marketplace. Present these as examples, not an exhaustive theme list or three built-in presets. Keep the screenshots uncropped, their theme names and origins visible, and the Windows capture label separate from overall platform availability. Retain the existing social-preview artwork.

## Placement

- The `#screenshots` section occupies the overview position after the hero, before `#workflows`. Integrate a short overview there once an actual recording is ready, keeping the theme screenshots available. Only then add a “Watch the overview” action.
- Pair focused recordings with `#parallel-agents`, `#persistent-work`, and `#connected-tools`. Keep their written explanations and documentation links.
- Show real footage from a named application version. Do not add blank players, fake screenshots, or unavailable-demo buttons.

## Playback and accessibility

- Prefer compressed WebM/MP4 over GIF. Use real poster frames and reserve the player’s aspect ratio to avoid layout shifts.
- Give users play/pause and fullscreen controls. Never autoplay audio or run multiple competing animations.
- Defer below-the-fold media loading. Offer a static poster for reduced-motion preferences.
- Caption narration and provide a text summary. Crop recordings so terminal text remains readable on a phone; allow expansion for detail.
- Keep thumbnails and video URLs stable. Consider a dedicated watch page for the overview if video search visibility becomes a goal; do not add video structured data before footage and metadata exist.

## Regression checks

Build and preview the site before testing search, because Pagefind is generated by the build. `site/tests/browser-checks.mjs` exports an async function accepting a Playwright Page and a local preview URL. It checks responsive layouts, screenshot selection and full-size viewing (including keyboard and no-JavaScript use), navigation, platform shortcuts, modal keyboard behavior, search results, missing-index handling, and stale-query cancellation. The function can be called from a Playwright harness or the connected browser tool; it needs no additional application dependency.
